# Product language

English is the canonical product language. Use concise, technical, calm, actionable copy. Prefer short status and action labels over conversational explanations.

- Name the state and next action directly: `Allow command?`, `Command failed · exit 1`.
- Put essential meaning in text; symbols and color reinforce it.
- Keep shortcut hints aligned with the active behavior and use the same key naming throughout.
- Keep user-facing strings near their owning surface until localization needs justify a message catalog. Avoid scattering equivalent wording across components.
- Do not dim critical errors, permission decisions, or required actions.
